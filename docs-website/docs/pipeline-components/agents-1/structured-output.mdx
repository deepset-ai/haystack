# Structured Output

`StructuredOutputHook` parses an Agent's final text reply as JSON, validates it against a Pydantic model or a JSON schema, and returns the result as an Agent output. Downstream components get a dict instead of a string, so you don't need a separate JSON parsing step after the Agent.

## Overview

Structured output is one use of the Agent's general [hooks](./hooks.mdx) mechanism. Registered under `on_exit`, `StructuredOutputHook` runs when the Agent is about to stop:

- If the Agent stopped with a text reply (`exit_reason` is `"text"`), the hook parses the reply as JSON and validates it against the schema. A markdown code fence around the whole reply, such as ```` ```json ````, is removed first. On success, it stores the result in the configured [`State`](./state.mdx) key. With a Pydantic model, the stored value is the validated model dumped to a dict.
- If the reply isn't valid JSON or doesn't match the schema, the hook can add a user message describing the error and keep the Agent running, so the model can correct its reply. `max_retries` sets how many times this happens. Retries count toward the Agent's `max_agent_steps`.
- If no retries are left, or the Agent stopped for any other reason (for example, a reply cut off by the model's output token limit), the hook stores `None` and logs a warning.

The hook works with any chat generator. When your chat generator supports native structured output, such as `text_format` on `OpenAIResponsesChatGenerator`, pass the same schema there too. The model is then constrained to produce valid JSON, and the hook turns it into an Agent output. Native structured output still lets the Agent call tools before it answers.

## Usage

### Basic setup

Declare the key the hook writes to in the Agent's `state_schema`. This makes it an Agent output you can read from the result or connect to another component in a pipeline. The hook writes to `structured_output` by default:

```python
from pydantic import BaseModel

from haystack.components.agents import Agent
from haystack.components.generators.chat import OpenAIResponsesChatGenerator
from haystack.dataclasses import ChatMessage
from haystack.hooks.structured_output import StructuredOutputHook


class CityInfo(BaseModel):
    city: str
    country: str


agent = Agent(
    chat_generator=OpenAIResponsesChatGenerator(
        model="gpt-5.4-nano", generation_kwargs={"text_format": CityInfo}
    ),
    state_schema={"structured_output": {"type": dict}},
    hooks={"on_exit": [StructuredOutputHook(schema=CityInfo, max_retries=2)]},
)

result = agent.run(
    messages=[ChatMessage.from_user("Which city is the Eiffel Tower in?")]
)

print(result["structured_output"])
# >> {'city': 'Paris', 'country': 'France'}
```

To rebuild the Pydantic model from the output, use `CityInfo.model_validate(result["structured_output"])`.

### Using a JSON schema

Pass a JSON schema dict instead of a Pydantic model, and use `state_key` to store the result under a different key:

```python
city_schema = {
    "type": "object",
    "properties": {"city": {"type": "string"}, "country": {"type": "string"}},
    "required": ["city", "country"],
}

agent = Agent(
    chat_generator=OpenAIResponsesChatGenerator(model="gpt-5.4-nano"),
    system_prompt="Answer only with a JSON object with the keys `city` and `country`.",
    state_schema={"city_info": {"type": dict}},
    hooks={
        "on_exit": [
            StructuredOutputHook(
                schema=city_schema, state_key="city_info", max_retries=2
            )
        ]
    },
)
```

Without native structured output, the system prompt asks the model for JSON, and retries cover the replies that don't match.

## Things to keep in mind

- **Register the hook last.** If you use other `on_exit` hooks, list `StructuredOutputHook` last so it parses the final reply after the other hooks have made their changes.
- **Retries are counted per turn.** The hook tags its correction messages and counts the ones added since the last user message. Correction messages from earlier turns of a conversation don't count. If a compaction hook removes correction messages from the conversation, the count starts over.
- **Cut-off replies aren't retried.** When the model hits its output token limit, the Agent stops with `exit_reason` set to `"length"`, and the hook stores `None` without retrying. Raise the token limit in the chat generator instead.
- **Serialization.** When you serialize an Agent with this hook, a Pydantic model is stored by its import path. Its module must be on the deserialization allowlist (`HAYSTACK_DESERIALIZATION_ALLOWLIST`) to load it again.
